# Combined release: 2026-11-15

This release integrates the outstanding sales/inventory/ZATCA branch, local
voucher commits, and the cost-center and interface work. The preview HTML entries
are development artifacts; the ordinary web build ships the real application.

## Database rollout

Back up the target PostgreSQL database and verify a restore before migration.
Apply these migrations as the schema owner, before the API and worker deploy:

- `20261114210000_provisional_inventory_costs`
- `20261114220000_unvalued_inventory_documents`
- `20261115100000_payment_counterparties`
- `20261115120000_cost_centers`

The migrations retain existing financial rows. They add inventory costing state,
relax the former negative-stock and mandatory-posting restrictions for the approved
provisional-cost policy, add voucher counterparties, and add cost-center links.
Historical vouchers retain their direction-based classification. Existing free-text
cost centers are not guessed into directory records.

## Release gates

- Lint, module boundaries, TypeScript, application build and locale parity.
- Real PostgreSQL integration tests using the restricted `erp_app` runtime role.
- Official ZATCA SDK 3.4.8 validation, including all six invoice/note combinations.
- Cost-center API validation/permission checks are a separate required CI step.
- Arabic/English voucher and cost-center browser checks against test fixtures.
- Dependency audit at the repository's high-severity threshold.
- Green CI on the combined PR before merge; confirm all three Railway application
  services run the resulting main commit, then perform authenticated read checks.

Local Windows runs need Java 11 on PATH and may need `OPENSSL_CONF` cleared for
the test process if another installed program points it at a missing file. Use
`--runInBand` for the Jest packages on a busy development machine; the original
concurrency assertions within the integration suites remain enabled.

## Production verification

Check readiness, login, company/account configuration, document lists and details,
stock pages, journals, voucher counterparties, cost centers, and compliance reads.
Render existing invoice PDFs in both languages and verify the interface styles on
the deployed application. Do not create test financial documents or submit test
invoices to the authority in production.

## Rollback boundary

Keep the pre-release application commit and the database backup. Before new
features create data, application rollback can leave the additional schema in
place. After negative inventory, unvalued documents, account-only vouchers, or
cost-center allocations are used, stop writes and review a forward correction
before reverting: older application code cannot safely interpret all new rows.
Never restore a backup over intervening financial transactions without explicit
reconciliation and an approved recovery window.

## Evidence

Local validation logs and screenshots are kept under the ignored `output/`
directory. Deployment, backup approval and live verification are operational
steps; their completion must be recorded after they actually occur.
